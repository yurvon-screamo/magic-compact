# План: порт Arkive Compact (magic-compact) на OpenCode V2

Статус: **утверждён code-quality-reviewer** (2 итерации: needs_work → ready, 2026-10-16).
База: форк imarshallwidjaja/magic-compact (Arkive v1.1.1 — 53 коммита поверх aerovato/magic-compact).
Лицензия: BSD-3 + NOTICE сохраняются.

## Контекст

- Нативный компакшн V2 — lossy блоб-саммари на ~90% контекста → «амнезия» вечных сессий зоопарка.
- Живой тест (16.10): `export → remove → import(тот же id)` = in-place rewrite транскрипта,
  id/title/time.created сохраняются, промпты работают. 409 на занятый id (идемпотентность).
- Механика Arkive: per-turn exact capsules (не генеративные саммари), omission-нотисы
  + retrievable-кэш, retention-оценка «не жать что не окупается», vision-aware.
- Потребители sessionID: TG-хаб (state.sessions), cron-плагин (задачи), фабрика —
  потеря id недопустима.

## Архитектура (решается срезом 0, дефолт hook-first)

**Путь А (дефолт):** нативный session hook `"compaction"` с подменой `result` —
плагин строит капсулы сам (`ctx.generate.text`, zai glm-5.3-flash) и отдаёт нативному
механизму. Ноль гонок, sessionID не трогается, оригиналы сообщений живы в транскрипте.

**Путь Б (если hook не покрывает):** roundtrip `export → transform → remove → import`
для всего. Roundtrip в любом случае остаётся для `/arkive:trim` (физическое удаление
тул-I/O).

Трим-ветка (roundtrip), только safe-by-construction:
1. Precondition: у сессии нет дочерних (subagent-спавны) — иначе отказ с диагностикой.
2. Export → transfer-файл на диск (бэкап; retention последние N=3 на сессию;
   неуничтожаем remove по построению).
3. Transform локально (чистая функция над массивом сообщений).
4. **Pre-flight import**: трансформированный payload → одноразовая сессия с подменённым
   id → 200 и валидность → только потом remove оригинала.
5. Перед remove: третья проверка inbox; непустой → дрен (GET inbox → DELETE inbox/{id}
   → повтор промптов после import).
6. Remove + import с родным id (окно «сессии нет» — миллисекунды).
7. Семафор per-sessionID.
8. Restore = обратный roundtrip из transfer-файла (E2E-тестируется, не только документируется).

**Residual risk (принято письменно):** промпт, admitted между дреном inbox и remove,
погибает тихо (200 был, сессии нет). Окно единицы миллисекунд; для личного стека
принимаем без верификации доставки. Ревью через N недель эксплуатации.

## Срезы

### Срез 0 — спайк (1–2 дня, гейт: письменное ADR)
- Hook «compaction»: покрывает ли exact-capsules через result; granular-контроль
  границы «что остаётся verbatim» (keep-policy Arkive).
- **Латентность/реентерабельность hook**: 3–5 последовательных ctx.generate.text внутри
  hook — замер, таймауты, дедлок-проверка (путь А должен работать с 10 капсулами,
  не только с одной).
- API-spike всех поверхностей: фактические имена событий (execution.succeeded),
  session.get outcome/idle, inbox shapes, ctx.session.wait, ctx.generate.text,
  revert/stage+commit (кандидат на замену trim-roundtrip), регистрация тулов/команд,
  TUI-тосты. Каждый контакт — живой smoke.
- Исход: ADR «путь А» или «путь Б» с обоснованием.

### Срез 1 — транспорт trim-ветки (гейт: все тесты зелёные)
Живые тесты на одноразовых сессиях:
- fork → parent/child → remove родителя → судьба форка (подтвердить рекурсивное
  удаление детей; поэтому бэкап = transfer-файл, не fork).
- Pre-flight import с подменённым id.
- **Вставка нового сообщения в СЕРЕДИНУ массива: сохраняет ли import порядок
  или пересортирует по time** (капсулы = вставка; от этого зависит срез 3).
- **Выживание image/vision-частей через roundtrip** (потеря картинок молчалива —
  форк vision-aware, это критично).
- Tool-пары (call/result): редактирование и удаление без поломки парности.
- Судьба System/Idle/Compaction-сообщений через roundtrip.
- **Restore E2E**: rewrite → порча → restore из transfer-файла → идентичность
  (id, messages) → промпт работает.
- Гонка-тест: промпт в окне remove→import → 404-контракт хаба (backoff 5с/30с/2мин,
  **после 3-го отказа — dead-letter файл ручного повтора**) и cron (пере-очередь
  задачи на след. тик) — оба поведения тестированы.

### Срез 2 — адаптационный слой V1→V2 (юнит, без API)
- Message union V2 (User/Assistant/Synthetic/Shell/System/Compaction/Idle/
  AgentSelected/ModelSelected/...) ≠ V1-шейпы: адаптационный слой, НЕ as-is.
- Фикстуры = реальные экспорты живых зоопарковых сессий (все виды сообщений).
- Pruning-правила Arkive + omission-кэш (retention: последние 2 компакшна;
  Content-ID = хэш содержимого — переживает rewrite).
- `read_omitted_content` по эвикнутому Content-ID → определённый «не найдено»,
  не падение.

### Срез 3 — капсулы
- ctx.generate.text (zai flash) для капсул; промпты из retention/ Arkive.
- Путь А: интеграция в hook. Путь Б: в transform.

### Срез 4 — команды и тулы
- /arkive:compact [N], /arkive:trim [N], /arkive:stats; TUI-тосты;
  read_omitted_content-тул.
- Очередь запросов на компакшн — в памяти (принятое ограничение личного стека),
  маркер в state-файле для наблюдаемости.

### Срез 5 — пилот (ru-сессия зоопарка)
- **Бейзлайн-неделя ДО пилота**; сессия с запасом контекста на бейзлайн+пилот,
  либо маркер нативного компакшна в бейзлайне (если случится — фиксируем и учитываем).
- Метрика: суммарная стоимость недели vs бейзлайн (кэш-инвалидация учтена),
  живость cron, доставляемость хаба.
- **QA-зонд деградации (детерминированный)**: фиксированный набор вопросов по
  скомпаченной истории в чек-поинтах — вместо субъективной «жалобы».
- Пороги отката: cron 404 >2 раз; QA-зонд провален 2 чек-поинта подряд;
  стоимость > бейзлайн ×1.3 → стоп → restore → разбор.

### Срез 6 — развёртывание
- Конфиг локации marketing (plugin[]); wiki-док (механика, restore-runbook,
  residual risk).

## Отказоустойчивость — контракты
- Хаб: 404 на session.prompt → backoff 5с/30с/2мин → dead-letter (персистентный
  файл), сообщение не роняется.
- Cron: 404 → задача пере-очередь (не умирает).
- Плагин: упавший import после remove → ретрай из transfer-файла (идемпотентен по 409).
